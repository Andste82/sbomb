### Milestone 16 — CMake Integration, GitHub Action, Release

**Goal:** the same binary works locally and in CI.

**Deliverables**

* `cmake/Sbomb.cmake` providing `sbomb_enable(TARGET <t> [CONFIG <file>] [POLICY <p>])`.

  **The tool never runs implicitly.** `sbomb_enable` does exactly two things: it makes the build *capable* of producing evidence, and it registers a **separate target**. It MUST NOT add a `POST_BUILD` step, so an ordinary `cmake --build .` never invokes `sbomb`.

  1. Evidence enablement on the named target: `-Wl,-Map=$<TARGET_FILE:t>.map` and `-Wl,--dependency-file=$<TARGET_FILE:t>.d` where supported, `CMAKE_EXPORT_COMPILE_COMMANDS=ON`, and a CMake File API query file written at configure time. Every linker flag MUST be probed with `check_linker_flag` and skipped with a `message(STATUS)` when unsupported — never assumed.
  2. A custom target `sbomb-<t>` that runs the generator on demand, plus an aggregate target `sbomb` depending on every registered `sbomb-<t>`. Both are `EXCLUDE_FROM_ALL`. Usage is `cmake --build . --target sbomb`.
  * `SBOMB_LINK_EVIDENCE` (default `ON`) turns off (1) for builds that must remain byte-identical to a reference build.
  * `sbomb_enable` MUST be a no-op with a warning when the target is an `INTERFACE` or `ALIAS` library.
* `.github/actions/sbomb/action.yml` — a composite action that downloads the pinned release binary (checksum-verified) and runs it. It MUST NOT reimplement any discovery logic.
* Reproducible cross-compiled release binaries for `linux/amd64`, `linux/arm64`, and `windows/amd64`. All are single static executables built with `CGO_ENABLED=0 -trimpath -buildvcs=false` and fixed `-ldflags`. Each release ships SHA-256 sums and a self-SBOM generated by the tool from its own build.
* Documentation: `docs/getting-started.md`, `docs/windows.md`, `docs/ci.md`, `docs/configuration.md`, `docs/findings.md`.

**Tests**

* An end-to-end test configuring and building `p01-hello` with the CMake module in a temp dir (requires a toolchain; tagged `//go:build e2e`).
* Action smoke test in CI on ubuntu and windows runners.
* Windows path test using `--path-flavor windows` on Linux: a build directory containing spaces, a drive letter, and a non-ASCII character.
* `sbomb_enable` adds no `POST_BUILD` step — asserted by building the fixture and checking that no SBOM was produced until `--target sbomb` is invoked.
* Release build reproducibility: two builds of the same commit produce identical binaries (`-trimpath`, `-buildvcs=false`, fixed `-ldflags`).

**Acceptance**

```
go test -tags e2e ./test/e2e/...                                                    # 0
scripts/release.sh --check-reproducible                                             # 0
```

CI workflow `action-smoke` green on ubuntu-latest. There is no Windows runner (§41 M14).

**Definition of Done:** identical configuration and policy behaviour locally and in GitHub Actions, with verified release artifacts.
